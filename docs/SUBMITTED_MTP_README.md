# Simply-Fit

Estimates a person's **approximate daily energy balance** (calorie surplus, deficit or maintenance, in kcal/day) from a sequence of daily body-weight readings, with an explicit statement of uncertainty and data reliability.

M.Tech project, extended from an internship project. This version audits the internship code, corrects its technical weaknesses, replaces the estimator, and evaluates everything on simulated data with known ground truth.

> **What the number is.** The output is an approximate energy-balance *equivalent* derived from the weight trend with a fixed 7,700 kcal/kg assumption. Weight alone cannot identify calorie intake, energy expenditure or exact physiological energy balance. All testing used computer-simulated weight logs; there is no real-world or clinical validation. Not medical advice.

## What the app does

1. You enter or upload daily weights (missed days allowed).
2. Readings are validated (non-numeric, implausible, duplicate-day entries are rejected with a message).
3. A robust (Huber) straight-line trend is fitted to the last 28 days by default.
4. The slope is converted to kcal/day and shown with an approximate 95% range.
5. A label is given: deficit, surplus, about maintenance, or *not yet clear* when the range does not support a call or fewer than 25 days are covered. Below 10 readings / 14 days no number is shown at all.
6. A reliability level (high / moderate / low) with the measured data-quality checks behind it.
7. Charts: readings with the fitted trend and its uncertainty; how the estimate moved over time.
8. Secondary: a 7-day forecast with a prediction band, and a coach that answers questions from the same computed numbers (templates by default; Google Gemini if you supply an API key).

## Setup

Python 3.10 or newer.

```bash
python -m venv venv
source venv/bin/activate            # Windows: venv\Scripts\activate
pip install -r requirements.txt     # app only
```

For tests, experiments and the optional LSTM:

```bash
pip install -r requirements-full.txt
```

## Run the app

```bash
streamlit run app/streamlit_app.py
```

On the "Weight log" step, type or paste readings (`78.4, 78.1, -, 78.3` where `-` is a missed day), upload a CSV with a `weight` column and optionally a `date` column, or load the clearly labelled simulated demo data.

Optional: put a Gemini API key in `.env` (see `.env.example`) or the sidebar to have the coach's wording generated by an LLM. This path was not tested in this project.

## Run the tests

```bash
pytest -q
```

158 tests: unit tests of the estimator, simulator, input parsing, forecaster and coach, plus integration tests that drive the whole Streamlit workflow headlessly. One test needs TensorFlow and the optional model and is skipped without them.

## Run the experiments

All commands from the repository root.

```bash
python -m experiments.audit_original                 # reproduces the defects of the original code (~3 min)
python -m experiments.run_experiments --stage all    # simulation experiments (~45 min on 2 cores)
python -m experiments.forecast_experiment            # forecast comparison (~1 min)
python -m experiments.forecast_reevaluation          # needs TensorFlow; re-scores and retrains the LSTM (~2 min)
python -m experiments.summarize                      # tables, figures, results/experiments/summary.json
python -m experiments.build_report                   # regenerates the four result documents from templates
```

One-minute smoke run of the same pipeline:

```bash
python -m experiments.run_experiments --stage all --quick
python -m experiments.forecast_experiment --quick
python -m experiments.summarize --quick
```

Seeds are fixed in `config/scenarios.json`; results are deterministic.

## Main results (simulation)

See `EXPERIMENT_RESULTS.md` for the full account, including where the corrected method is not better. In brief: the corrected estimator is clearly more accurate when days are missed or readings contain gross errors, about equal on complete clean logs, and its uncertainty statements are far closer to honest than the original's, though still somewhat too narrow.

## Known limitations

- Evaluated on simulated data only.
- 7,700 kcal/kg is an assumption; individual values differ and the stated range does not include that.
- The approximate 95% range contained the simulated truth less often than 95%.
- Changes in body water (starting or stopping a diet, salt, illness, hormonal cycles) are indistinguishable from changes in energy balance over days to weeks.
- About four weeks of regular readings are needed before the app commits to a deficit or surplus.
- The guideline notes shown for medical conditions are a small list whose sources were not verified here.
